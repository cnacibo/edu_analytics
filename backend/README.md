# 📖 FRONTEND
В этом блоке лежит `FastAPI` проект бэкенда приложения. Ниже будет написано краткое описание работы блока и выбранных библиотек.

## Структура блока:
```commandline
├── Dockerfile
├── README.md
├── alembic/
├── alembic.ini
├── app
│   ├── api
│   │   ├── hse_analysis.py
│   │   ├── statistics.py
│   │   └── vuzopedia_analysis.py
│   ├── db
│   │   ├── crud.py
│   │   ├── models.py
│   │   └── session.py
│   ├── main.py
│   ├── schemas.py
│   └── services
│       ├── hse_service.py
│       ├── shared.py
│       ├── statistics_service.py
│       └── vuzopedia_service.py
├── entrypoint.sh
└── scripts
    └── load_data.py
```
Бэкенд работает с `PostgreSQL`, использует асинхронный драйвер asyncpg и управляет схемой БД через `Alembic`.
Все файлы с данными монтируются из общей папки `storage/files/` на уровне проекта.

---
## 🔍 Модули

### 1️⃣ app/api

> Содержит обработчики HTTP-запросов, сгруппированные по источникам данных и функциональности

- `hse_analysis.py` – эндпоинты для работы с программами НИУ ВШЭ (список, детали, курсы).
- `vuzopedia_analysis.py` – эндпоинты для работы с программами из Vuzopedia (список, детали).
- `statistics.py` – статистические данные для дашборда.

Каждый роутер подключается в `main.py` с префиксом `/api`, а именно:
- /api/hse
- /api/vuzopedia
- /api/stats

---

### 2️⃣ app/services

> Содержит функции, вызываемые из роутеров

- `hse_service.py` / `vuzopedia_service.py` – логика работы с данными из БД.
- `statistics_service.py` – логика работы с `ml` блоком: вызов `AnalysisService`.
- `shared.py` – общие утилиты.

Сервисы изолированы от роутеров, что упрощает тестирование и переиспользование.

---

### 3️⃣ app/db

> Модели SQLAlchemy, CRUD-операции и управление сессиями

- `models.py` – SQLAlchemy ORM-модели (программы, курсы и т.д.).
- `crud.py` – функции для чтения записей.
- `session.py` – настройка асинхронной сессии (`sessionmaker`) и получение `db` dependency для FastAPI.

БД инициализируется через `Alembic` миграции (папка `alembic/versions/`).
При запуске контейнера миграции применяются автоматически.

---

### 4️⃣ alembic

> Инструмент для версионирования изменений структуры БД

Миграции запускаются в `entrypoint.sh` командой `alembic upgrade head` перед стартом приложения.

---

### 5️⃣ scripts/load_data.py

> Скрипт для первоначальной загрузки данных из CSV в БД

Запускается при старте контейнера, если в папке `storage/files/` есть файлы с данными.
Обрабатывает информацию из CSV файлов и заполняет ею созданные в БД таблицы.

---

### 6️⃣ entrypoint.sh

> Точка входа в контейнер

Выполняет следующие команды:

- Ожидание доступности PostgreSQL (`pg_isready`).
- Применение миграций `Alembic`.
- Загрузку данных из CSV файлов.
- Запуск `Uvicorn` сервера.

## 📦 Используемые библиотеки

| Библиотека | Назначение | Почему выбран |
|------------|------------|----------------|
| **FastAPI** | Веб-фреймворк | Асинхронный, современный, автоматическая генерация OpenAPI-документации |
| **Uvicorn** | ASGI-сервер | Высокая производительность, поддержка `--reload` для разработки |
| **Pydantic** | Валидация данных и схемы | Строгая типизация, удобное преобразование между JSON и Python-объектами |
| **asyncpg** | Асинхронный драйвер PostgreSQL | Быстрый, надёжный, поддерживает асинхронные запросы |
| **SQLAlchemy** | ORM | Гибкий, поддерживает асинхронный режим через `asyncpg` |
| **Alembic** | Миграции БД | Стандартный инструмент для SQLAlchemy, удобное версионирование схемы |
